### 0.2 端口是临时的，必须先知道

正常端口是 **55432**，但它现在落在 Windows 的保留区间 `55408–55507` 里——Docker Desktop
启动时 Hyper-V/WSL 动态占用了这一段，Postgres 因此无法绑定（日志报 `Permission denied`，
不是"已有实例在运行"）。

当前是用 **55532** 临时绕过的，**没有修改任何配置文件**。这意味着：

- `start-odoo19-dev.ps1` 直接运行**会失败**，因为它写死了 55432；
- Agent 必须带 `ODOO_DB_PORT=55532` 启动，否则连不上库。

**持久修复**（需要管理员 PowerShell，一次性）：

```powershell
net stop winnat
netsh int ipv4 add excludedportrange protocol=tcp startport=55432 numberofports=1 store=persistent
net start winnat
```

第二条把 55432 永久登记为排除端口，Hyper-V 以后不会再抢它。做完之后就可以回到
标准流程，本文其余部分不受影响。

### 0.4 先读这一段，避免把已知现象当成缺陷

| 现象 | 是不是缺陷 |
| --- | --- |
| 一个数据问题要等 **15～25 秒** | **不是**。当前 `LLM_PROVIDER=siliconflow`，实测每道 KPI 约 20s 且每次都要一轮 SQL 修复；换成 deepseek 约 5.8s 且无需修复。详见 [19 §2.4](19-current-status-and-open-gaps.md)。这是待你决策的事项，不是 bug |

| 问 2025 年之前的数据返回空 | **不是**。数据只从 2025-10 开始 |
| 脚本退出时报 `ResourceTracker.__del__` | **不是**。Python 3.12 的清理噪音，退出码仍为 0 |

## 2. 数据准确性（UAT-01 核心，最重要的一节）

**这是发布前置。** 在智能助手里逐题提问，把答案和"标准答案"列对照。

标准答案全部由 SQL 直接从 `odoo19_dev` 算出，口径为：**已确认订单**（`state IN ('sale','done')`）、
**未税金额**（`amount_untaxed`）。今天是 **2026-09-09**。

> **口径分歧比数字错误更值得记录。** 如果 Agent 算出别的数，先判断是它错了，
> 还是它用了不同但合理的口径（比如含税、或把草稿单也算进去）。后者要记下来，
> 那是我们需要统一的业务定义。

那次运行里；页面显示的是**最近一次**，而最近一次（`170814`）是不带 `--ragas` 的
检索验证跑，所以 RAGAS 一栏是"未运行"。

这暴露了一个真实的小问题：**跑一次不带 `--ragas` 的评测，会把已有的 Faithfulness
基线从页面上盖掉**。页面本身没错（它如实显示最近一次，且明确区分了"未运行"和
"分数为 0"），但"最近一次"未必是"最近一次有 RAGAS 的"。已记入 [20](20-next-actions.md) 待办。

想在页面上看到 0.9075，重跑一次带 RAGAS 的即可（约 30～40 分钟，消耗模型额度）：

```powershell
.\.venv\Scripts\python.exe .\evals\run_wiki_rag_eval.py --mode hybrid --ragas --ragas-max-cases 5
```

## 8. 记录与反馈

测试时请按这个格式记录问题，便于我直接定位：

```
[编号] 2.1.3
提问：上个月销售额是多少？
期望：138,451.00
实际：152,296.15
截图/Trace：<Langfuse 链接>
备注：怀疑把含税金额算进去了
```

**优先反馈这三类**：

1. **第 2 节的数字不一致** —— 直接影响能不能发布
2. **第 6 节的任何异常** —— 安全边界被突破
3. **口径分歧**（数字不同但双方都说得通）—— 需要你拍板定义

其余（措辞、排版、速度）可以攒一批一起说。
