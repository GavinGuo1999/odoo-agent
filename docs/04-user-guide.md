# 用户使用手册

> 适用应用版本：0.2.0
> 应用地址：<http://127.0.0.1:8090/ui/index.html>

## 1. 页面导航

| 页面 | 用途 |
| --- | --- |
| 工作台 | 查看关键指标、趋势、最近订单和推荐问题 |
| 智能助手 | 普通聊天、指标解释、Odoo 实时数据分析 |
| 销售看板 | 固定结构的销售 KPI、趋势、排名、状态和待办 |
| 数据与模型 | 配置模型、Langfuse、Odoo 数据源和状态库 |

## 2. 工作台

工作台用于快速了解销售概况，不经过 Text2SQL 模型，直接调用后端固定销售看板接口。

主要区域：

- 本月销售额；
- 已确认订单；
- 平均订单金额；
- 待交付订单；
- 近六个月销售趋势；
- 最近销售订单；
- 常用问题快捷入口。

“正在读取”消失后，页面数据来自当前 Odoo 数据库。如果读取失败，优先到“数据与模型”检查 Odoo 连接。

## 3. 智能助手

### 3.1 三类问题

| 类型 | 示例 | 系统行为 |
| --- | --- | --- |
| 普通问答 | “今天是几月几号？” | 直接调用普通聊天模型，不查询 Odoo |
| 指标口径 | “销售额如何定义？” | 从固定销售语义层解释，不生成 SQL |
| 数据分析 | “本月销售额是多少？” | 生成 QueryPlan 和只读 SQL，查询真实 Odoo |

系统自动判断类型，不需要用户选择“聊天”或“BI”。

### 3.2 实时进度

数据问题可能显示以下阶段：

```text
正在判断问题类型
正在检查 Odoo 只读连接
正在检索销售语义与字段
正在生成查询计划和 SQL
正在执行只读 SQL 安全校验
正在查询 Odoo 实时销售数据
正在生成确定性结果摘要 / 正在整理销售分析结论
回答已完成
```

如果 SQL 首次未通过校验，还会显示“SQL 未通过校验，正在安全修复”。

### 3.3 回答内容

一个完整数据回答可能包含：

- 文字结论；
- QueryPlan 标识和指标口径；
- KPI、折线图、柱状图或饼图；
- 数据表格；
- 查询行数和耗时；
- 可展开的只读 SQL；
- 模型供应商和 Model ID；
- 估算 Cost；
- Langfuse Trace 链接；
- 👍 / 👎 反馈。

### 3.4 `data_accessed` 的含义

- `true`：本轮确实执行了 Odoo 只读 SQL；
- `false`：普通问答、指标解释、数据库不可用、安全校验失败或其他未查询情形。

只有 `data_accessed=true` 的回答才能被当作真实业务查询结果。

## 4. 如何提出更好的问题

推荐包含以下信息：

```text
时间范围 + 指标 + 维度/对象 + 排序或比较方式
```

### 4.1 好的示例

- “本月已确认订单的未税销售额是多少？”
- “今年每个月的销售额和订单数趋势怎么样？”
- “最近三个月销售额最高的十个客户是谁？”
- “按销售数量列出本月前十个产品。”
- “上个月各销售员的销售额和订单数。”
- “哪些订单已交付但还没有完全开票？”

### 4.2 容易产生歧义的示例

- “销售怎么样？”——缺少时间范围和指标；
- “那个客户呢？”——当前上下文可能没有唯一客户；
- “收入多少？”——可能指订单额、开票额或收款额；
- “全部明细”——时间范围和返回规模不明确。

系统在关键歧义时会暂停询问，而不是直接猜测。

## 5. 指标口径

当前默认使用已确认销售订单状态 `sale`、`done`。

| 指标 | 默认定义 |
| --- | --- |
| 销售额 | `SUM(sale_order.amount_untaxed)` |
| 含税销售额 | `SUM(sale_order.amount_total)` |
| 订单数 | `COUNT(DISTINCT sale_order.id)` |
| 平均订单额 | 销售额 ÷ 订单数 |
| 销售数量 | 非展示订单明细的订购数量 |
| 已交付数量 | 非展示订单明细的 `qty_delivered` |
| 已开票数量 | 非展示订单明细的 `qty_invoiced` |

默认时间字段为 `sale_order.date_order`，时区为 `Asia/Shanghai`。更详细的口径见 [数据语义与安全](06-data-and-security.md)。

## 6. 图表和表格

系统根据结果形状自动选择：

| 结果形状 | 默认图表 |
| --- | --- |
| 单个值 | KPI |
| 时间 + 数值 | 折线图 |
| 分类 + 数值 | 柱状图 |
| 少量占比分类 | 饼图 |
| 不适合图表 | 仅表格 |

图表只是对同一结果行的可视化，表格是核对精确值的依据。SQL 可用于开发者或数据负责人复核口径。

## 7. 简单回答和复杂回答

### 7.1 确定性回答

以下结果通常跳过第二次模型：

- 单行 KPI；
- 单指标 Top N；
- 单指标简单趋势；
- 空结果。

回答元数据显示“确定性摘要”。优点是更快、更便宜，并减少模型对数字的二次改写。

### 7.2 模型解释

多指标比较、复杂结果或需要洞察时，系统调用“复杂结果解释”模型。该模型只能看到问题、SQL 和受限结果行，仍应以表格和 SQL 为最终核对依据。

## 8. Interrupt：系统要求补充信息

当页面显示澄清问题时：

1. 阅读系统指出的歧义；
2. 在同一输入框直接回答，例如“按订单未税金额”“只看 2026 年 7 月”；
3. 不要点击“新建会话”；
4. 系统使用原 `session_id` 恢复暂停的 Graph；
5. 恢复后会重新检索语义、生成并校验 SQL。

Interrupt 不是错误，而是系统拒绝在关键业务条件不清楚时猜测。

## 9. 会话与追问

- 浏览器为聊天保存一个 Session ID；
- 左侧“对话”区域可以新建、切换和删除历史会话；
- 刷新页面后，前端通过后端状态库恢复历史；
- 后端重启后，PostgreSQL Checkpointer 仍可恢复会话；
- 回答生成中也可以切换会话，原回答会在后台继续；
- 生成中刷新页面时，当前问题会先被保留，并显示运行或中断状态；
- 点击“新建会话”会生成新的 Session ID；
- Langfuse 中同一聊天的多轮 Trace 按 Session 聚合。

追问示例：

```text
用户：今年每个月销售趋势怎么样？
用户：那上个月呢？
用户：只看销售员 Alice。
```

追问越短，对历史上下文依赖越强。若上下文不足，系统可能要求澄清。

## 10. 点赞、点踩和 Trace

### 10.1 反馈

- 👍 表示回答可以接受；
- 👎 表示回答存在问题；
- 反馈写入对应 Langfuse Trace 的 BOOLEAN `user-thumbs` Score；
- API Key 只在后端使用，不会进入浏览器。

建议在点踩后记录问题类型，例如数字、口径、SQL、没有回答问题或速度慢。当前页面只提供布尔按钮，详细原因可先通过 Langfuse Comment 补充，未来再增加前端原因选项。

### 10.2 Trace 链接

点击“打开 Langfuse Trace”可检查：

- 本轮输入和最终输出；
- 每个 Agent/Tool/Retriever/Generation；
- SQL 模型和解释模型是否按路由执行；
- Token、Cost 和耗时；
- SQL 安全校验、执行结果和错误；
- 用户反馈 Score。

## 11. 切换模型

进入“数据与模型 → 节点级模型路由”。推荐先只改变一个角色，再使用同一批问题比较：

- SQL 正确率；
- QueryPlan 结构成功率；
- 延迟；
- Token 和 Cost；
- 用户点赞率。

不要只因为模型回答文字更漂亮就替换 SQL 模型。Text2SQL 的核心指标是语义、SQL 安全、执行和结果正确性。

## 12. 销售看板

销售看板是固定查询，不调用 LLM。支持：

- 周 / 月 / 季度；
- 销售员筛选；
- KPI 与同比期比较；
- 趋势；
- 订单状态；
- 客户和产品排名；
- 待交付、待开票等关注项；
- 最近订单；
- CSV 导出。

固定看板适合日常稳定查看；智能助手适合临时问题和自由维度组合。

## 13. 常见问题

### 13.1 为什么只有 Token，没有 Cost？

检查设置页对应供应商的输入/输出百万 Token 单价是否大于 0。历史 Trace 不会自动补写新成本；请查看修改配置后的新 Trace。

### 13.2 为什么查询结果为空？

先看表格、SQL、时间范围和公司 ID。空结果会明确回答“没有查到符合口径的数据”，不会用示例数字替代。

### 13.3 为什么 SQL 被修复？

首次模型输出可能缺少公司过滤、包含不开放字段或结构不合法。系统最多修复两次，每次仍要重新通过同一套确定性 Guard。

### 13.4 为什么没有图表？

结果形状可能不适合白名单图表，或者查询失败、无数据、列不满足图表规则。表格和 SQL 仍会保留。

### 13.5 为什么刷新后历史没有恢复？

到设置页确认 Agent 状态库显示“PostgreSQL 已连接”。如果为 memory，刷新仍可能恢复当前进程状态，但后端重启后会丢失。PostgreSQL 模式下，问题会在模型调用前写入状态库；即使生成中刷新，问题和会话标题也应保留。

### 13.6 能否修改 Odoo？

不能。当前系统只接受一条 SELECT，并同时使用 SQL Guard 和数据库只读事务阻止写操作。

## 14. 使用边界

- 结果仅覆盖已开放的销售数据和固定公司；
- 模型解释可能不完整，关键数字以表格和 SQL 为准；
- 当前无登录，不应暴露到不可信网络；
- 当前不是财务报表系统；
- 当前不执行 Odoo 写操作。
