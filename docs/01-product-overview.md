# 产品与范围

> 适用应用版本：0.2.0
> 目标读者：项目负责人、产品、业务负责人、开发人员

## 1. 产品定位

Odoo Sales Agent 是一个面向 Odoo 销售数据的本地网站型 Agent。用户可以直接用中文提问，系统判断问题属于普通聊天、指标口径解释还是数据分析；对于数据问题，系统从只读 Odoo PostgreSQL 生成并执行安全 SQL，再返回可追溯的结论、表格、图表和 SQL。

当前版本优先解决“先把销售 ChatBI 功能做通”，不以多用户、权限体系或大规模部署为目标。

## 2. 当前业务假设

| 维度 | 当前约束 |
| --- | --- |
| 用户 | 单用户，不登录，不区分角色 |
| 公司 | 单公司，通过固定 `company_id` 限制 |
| 数据域 | 销售订单、销售明细、客户、产品、销售员、公司、币种、单位 |
| 数据新鲜度 | 直接查询 Odoo PostgreSQL，接近实时 |
| 数据规模 | 小数据量，功能和正确性优先 |
| 数据访问 | 第一阶段严格只读 |
| 部署 | Windows 本地运行，监听 `127.0.0.1:8090` |
| 模型 | DeepSeek API 或硅基流动 OpenAI 兼容接口 |
| 图表 | 前端 ECharts，不依赖 Metabase |
| 可观测性 | Langfuse Cloud EU 或兼容的自托管地址 |

## 3. 产品目标

### 3.1 主要目标

- 让非技术用户用自然语言查询 Odoo 销售数据。
- 所有业务数字必须来自真实只读查询，禁止生成演示数字或模型猜测数字。
- 让用户看得到执行阶段、查询结果、SQL、数据口径和模型来源。
- 通过语义层和确定性校验稳定 Text2SQL，而不是完全依赖模型自由发挥。
- 通过 Langfuse 和黄金问题集，使质量、延迟、Token、Cost 和用户反馈可量化。
- 支持刷新页面或重启后恢复同一会话，并在关键歧义处暂停向用户确认。

### 3.2 非目标

当前版本明确不负责：

- Odoo 账号登录、SSO、RBAC、行级权限和多租户隔离；
- 修改、审批、创建或删除 Odoo 业务数据；
- 采购、库存、会计、制造等完整跨域分析；
- 面向公网的安全部署和高并发服务；
- 通用任意数据库查询；
- 替代正式财务报表、审计报告或法定报表；
- 自动执行高风险业务动作。

## 5. 典型使用场景

### 5.1 普通问答

示例：“今天是几月几号？”“你使用的是什么模型？”

系统不会连接 Odoo 数据库执行业务 SQL，只调用普通聊天模型。响应中 `intent=general`、`phase=general-chat`、`data_accessed=false`。

### 5.2 指标口径

示例：“销售额是怎么定义的？”“客单价怎么算？”

系统从版本化销售语义层返回口径，不生成 SQL。响应中 `intent=semantic`、`phase=semantic-layer`、`answer_mode=semantic`。

### 5.3 KPI 查询

示例：“本月销售额是多少？”

系统生成 QueryPlan 和 SQL，完成安全校验和真实查询。若结果为简单 KPI，则程序确定性总结并跳过第二次 LLM。

### 5.4 排名与趋势

示例：“销售额最高的十个客户是谁？”“今年每个月销售趋势怎么样？”

系统返回 ECharts 柱状图或折线图，同时保留表格和 SQL。简单单指标排名/趋势通常使用确定性回答。

### 5.5 歧义确认

示例：“那个客户怎么样？”或模型判断销售额口径、对象或时间范围无法安全推断。

LangGraph 产生 Interrupt，网页展示澄清问题；用户补充后使用相同 `session_id` 恢复原工作流。

## 6. 质量目标

| 指标 | 当前门槛 / 目标 |
| --- | --- |
| SQL 写操作拦截 | 100% |
| 非白名单表字段拦截 | 100% |
| 销售事实查询公司过滤 | 100% |
| 自动测试 | 提交前全部通过；当前 45 项 |
| 黄金问题静态检查 | 100%；当前 20/20 |
| QueryPlan 结构合法 | Pydantic 严格校验，失败进入修复或安全失败 |
| 数据真实性 | `data_accessed=true` 时只使用真实 SQL 结果 |
| 可追溯性 | 正常配置 Langfuse 时，每轮返回 Trace ID/URL |
| 简单查询模型次数 | 通常 1 次 SQL Generation |
| 服务降级 | Langfuse 不可用不阻断回答；状态库不可用降级内存模式 |

## 7. 成功标准

项目在当前阶段被认为成功，需要同时满足：

1. 用户能够用中文完成销售 KPI、排名、趋势和履约查询；
2. SQL 安全规则和数据库只读规则同时生效；
3. 回答中不出现脱离查询结果的业务数字；
4. 模型、SQL、耗时、Token、Cost 和用户反馈可在 Langfuse 追踪；
5. 模型或 Prompt 变更前后能够使用同一黄金集对比；
6. 后端重启后能够读取已有会话；
7. 错误和歧义以明确状态返回，而不是伪造成功答案。

## 8. 术语

| 术语 | 定义 |
| --- | --- |
| ChatBI | 通过对话完成指标查询、数据分析和可视化 |
| Text2SQL | 将自然语言数据问题转成 SQL |
| QueryPlan | 模型输出的结构化查询计划，包含类型、指标、维度、过滤和时间范围 |
| 语义层 | 版本化的开放表、字段、关系、指标定义和验证示例 |
| Guard | SQL 执行前的确定性安全校验器 |
| Checkpointer | LangGraph 状态持久化组件 |
| Interrupt | 工作流暂停并等待用户提供澄清信息 |
| Trace | 一轮用户问答的完整可观测记录 |
| Observation | Trace 内的 Agent、Generation、Retriever 或 Tool 步骤 |
| 黄金问题 | 有明确预期行为、用于持续回归的业务问题 |
